## 动手之前，先把这四件事做掉

迁移失败的案例，十有八九是准备没做足，操作本身反而不难。

1. **做一次完整备份**。先用主机商自带的快照或备份功能存一份当前版本，再用搬家插件备一份。双保险的意义在于：任何一步搞砸了，你都有退路。
2. **清理站点**。删掉没在用的主题、插件和媒体文件。站点越小，打包、上传、还原每一环都快，出错的概率也低。
3. **新主机装好空壳 WordPress**，并装上和旧站相同的搬家插件。
4. **记下当前配置**。固定链接结构、小工具、主题设置，截图或抄下来；迁移期间建议停用缓存插件，免得旧缓存干扰判断。

## 方法一：插件搬家，新手优先走这条

插件搬家把文件和数据库打成一个包处理，全程不用碰 phpMyAdmin，对没有技术基础的人最友好。

### All-in-One WP Migration：导出再导入

1. 旧站后台安装并启用插件，进 All-in-One WP Migration → Export → FILE，整站打包成 .wpress 文件。Advanced options 里可以勾掉文章修订版本之类的内容，包体能小一圈。
2. 打包完成后点 Download，下载到本地。
3. 新主机安装同一个插件，进 Import → IMPORT FROM → FILE，选中刚才的 .wpress 上传。
4. 进度到 100% 后点 PROCEED，等导入跑完。
5. 导入成功后，新站的后台账号密码就是你旧站的那一套，直接登录。

两个限制要提前知道：

- **免费版有导入上限**。新版大约卡在 256MB，部分版本显示 512MB，具体以你导入页面显示的最大上传大小为准。超出就得买官方的 Unlimited Extension（约 $69），装上后上限放宽到 25GB。
- **导入页显示的限制可能来自服务器**。那个数字有时是 PHP 的 upload_max_filesize，和插件本身无关。这种情况先调大服务器的上传限制；某些主机也可以装官方免费的 File Extension（Basic）绕过去。

进度条长时间停在某个百分比（比如 80%）不动是高频问题，别傻等。把备份文件压成 zip，通过下面任意一种方式传进新站的 /wp-content/ai1wm-backups/ 目录，再到插件的 Backups 页面点 Restore：

- 后台装个 File Manager 插件直接上传；
- 用主机面板自带的文件管理器；
- FTP 上传。站点大的时候 FTP 支持断点续传，比浏览器上传稳得多。

### UpdraftPlus：按类型分开备份

流程类似，但备份文件会分成数据库、插件、主题、其他四类：

1. 旧站点 Backup Now，勾选数据库和文件，再勾上“仅手动删除”；
2. 备份完成后把四类文件全部下载到本地，搬家场景一份都不能少；
3. 新主机装同款插件，点 Upload backup files 上传，然后 Restore，四类全勾，按提示走完。

想省掉“下载再上传”这一步，UpdraftPlus 家的付费 Migrator 支持远程直迁，属于花钱买时间的选项。

## 方法二：手动搬家，大站和不想受限的人用

手动搬家的逻辑很朴素：WordPress 核心程序不用动，真正要搬的只有 wp-content 文件夹和数据库。

准备三样东西：FTP 工具（FileZilla 就够用）、phpMyAdmin、一个代码编辑器（Notepad++，别拿 Word 改配置文件）。

1. FTP 连上旧主机，把整站文件下载下来，重点是 wp-content；
2. 进 phpMyAdmin，选中网站数据库点 Export，导出 .sql 文件。分不清哪个库属于哪个站，就打开库里带 options 的表，home 字段里写着域名；
3. 把文件传到新主机的网站根目录。传压缩包的话，传完在文件管理器里在线解压，注意解压后的目录结构必须和原来一致——wp-admin、wp-content、wp-includes 加一堆单文件直接躺在根目录，别套多一层；
4. phpMyAdmin 里 Import 导入 .sql；
5. 编辑新站的 wp-config.php，把数据库名、用户名、密码换成新主机的。如果建站时数据库名是系统自动生成的，导入后报数据库错误，八成是这里没改对。

cPanel 用户有捷径：旧账户用备份向导生成完整备份，新账户用同一个向导分别还原主目录文件和 MySQL 数据库，最后照旧改 wp-config.php。

用宝塔面板的再补一句：备份还原都能在面板里点完成；还原完检查一下网站目录的文件属主是不是 www、权限是不是 755（.user.ini 保持 root 和 644）。属主不对，站点会出一些莫名其妙的问题。

## 不停机的关键：切域名前，先让新站“只给你自己看”

整个迁移里最容易被跳过的一步：域名还指着旧主机时，用临时方式访问新主机，把新站完全搭好、验证无误，再动解析。

常见做法有三种：

- 托管主机自带临时域名。SiteGround、Cloudways 这类主机后台会直接给你一个临时二级域名，后面拼上 /wp-login.php 就能登新站后台；
- 宝塔+VPS 用 IP 加端口访问，等解析切完再把这条配置删掉；
- 改本机 hosts 文件，让只有你这台电脑把域名指向新 IP，其他访客照旧走旧站。

hosts 的具体操作：

1. 以管理员身份打开 C:\Windows\System32\drivers\etc\hosts；
2. 末尾加一行：新主机 IP 加你的域名（带 www 和不带 www 各写一条）；
3. Win+R 调出运行窗口，输入 cmd 回车，执行 ipconfig /flushdns 刷新 DNS 缓存；
4. 无痕模式访问你的域名，看到的就应该是新主机上的站。

> 大陆用户注意：hosts 方法成立的前提是电脑能直连新主机 IP。主机在香港可以直连；主机在美国时，如果你挂着代理上网，代理会让 hosts 解析失效——很多人改了半天发现“没生效”，问题出在自己没连对网络，而不是 hosts 没改好。

临时访问实在搞不定的兜底方案：提前把 DNS 切到新主机。代价是从切换到搬完这段时间，访客会看到新主机的白板站。挑凌晨这类流量低谷动手能少点尴尬；站点本来就是新的，那完全无所谓。

## 最后切域名，改两条记录就够

新站验证完毕，把域名解析指向新主机 IP，迁移正式完成。

用 Cloudflare 管理解析（推荐顺手开启）：进后台改两条记录——A 记录 @ 指向新主机 IP；CNAME 记录 www 指向主域名。这样不管访客输不输 www 都能到新站，橙云保持开启还能蹭 CDN 加速和基础防护。

没用 CDN 的，去域名注册商后台找 DNS 管理入口，把 A 记录改成新主机 IP；CNAME 动不动，取决于你是否让用户通过 www 子域名访问。

解析生效时间有快有慢，几分钟到几个小时都可能。期间新旧站交替出现属于正常现象，别慌着回滚。

## 迁移完成，这五件事检查完再收工

导入成功只算完成了一半，下面的收尾动作决定迁移质量：

1. 到设置 → 固定链接重新保存一次。用自定义结构的先把结构复制出来，换其他结构保存、刷新页面、再粘回去保存——这一步能重建 .htaccess，避免内页 404；
2. 用旧站账号密码登新站后台，前后台各点一圈，重点看图片、菜单和表单；
3. 把留在服务器上的备份文件删掉。备份包被人下走，等于整个站拱手送人；
4. 宝塔用户核对文件属主和权限；
5. 确认解析在全球生效、新站稳定跑几天后，旧主机到期就不用续了。

## 常见问题

### All-in-One WP Migration 免费版到底能搬多大的站？

以你导入页面显示的上限为准，新版普遍在 256MB 一档，部分版本是 512MB。超限后不建议去改插件代码绕过——尺寸常量随版本更新会变，改错一次可能把数据搞坏，$69 的 Unlimited Extension 是更稳妥的解法。

### 备份文件太大，上传总是失败怎么办？

三条路：把备份压成 zip，传进 /wp-content/ai1wm-backups/ 再到 Backups 页面 Restore；走 FTP 上传，支持断点续传；或者干脆换手动搬家，文件和数据库分开处理，完全不挑体积。

### 改了 hosts 还是访问旧站，怎么回事？

按顺序排查：hosts 文件是否保存成功；DNS 缓存是否刷新（ipconfig /flushdns）；是否开着代理。大陆用户挂代理时 hosts 基本失效，先确认能直连主机 IP 再测。

### 导入完成后后台密码不对？

All-in-One WP Migration 导入的新站，后台账号密码和旧站完全一致。登不上多半是你在试新主机建站时设的那套，换旧站的试试。只有导入别人做的模板站，才需要进数据库手动改账号密码。
